# Contributing

Thanks for looking at `dsh-skill-dashboard`. This is a read-only dashboard: it
reads skills and session logs, and writes only its own override, cache and
snapshot files. That boundary is not negotiable; see
[ADR 0001](docs/adr/0001-read-only-dashboard.md).

## Setup

- Node 22+ (the repo has no runtime dependencies).
- Work from the repo root.

```bash
npm run build   # rebuild client.js from src/client/ fragments
npm run check   # build sync + syntax + taxonomy + package contents + tests
```

In a restricted Windows sandbox, Node's default test runner can hit
`spawn EPERM`; use:

```bash
node --test --test-isolation=none
```

Never hand-edit `client.js`. It is generated by
`scripts/build-client.mjs` from `src/client/*.js` and committed so the Host can
serve one file. A change is not complete until `npm run build` has run.

## Where things live

| Path | Purpose |
| --- | --- |
| `index.js` | Host plugin: routes, catalog, usage, overrides, translation, plans |
| `lib/` | Pure logic: compose, usage, override store, translation, snapshots, capabilities |
| `src/client/` | Client fragments; `50-dashboard.js` is the component, `32-data.js` the data hook |
| `test/` | Unit tests plus a route integration suite (`test/routes.test.js`) |
| `taxonomy.json` | Situation titles and known skill mappings |
| `locale/` | Host locale strings |
| `docs/adr/` | Decisions that are hard to reverse |
| `tools/` | Packaging, taxonomy checks, screenshots |

Start with `docs/HANDOFF.md` for the architecture and the current limits.

## Making a change

1. **Public behavior** gets a test at the seam it is observed through:
   - a pure helper → its module test (`test/*.test.js`);
   - an HTTP route → `test/routes.test.js` with the fake `ctx`;
   - the client render → `test/client.test.js` (the smoke harness loads the
     real `client.js`).
2. Run `npm run check`.
3. If behavior changes, update `README.md`, `README.zh-CN.md` and
   `docs/HANDOFF.md`. If a term changes, update `GLOSSARY.md`. If a decision is
   hard to reverse, add an ADR.
4. Keep the client fragments small; put pure decisions in `26-view-model.js`
   or `27-usage-profile.js`, not in the component.

### Translation rules

- No model request without an explicit user confirmation (`consent: true`).
- Only `name`, `description` and `whenToUse` leave the machine.
- Keep the content-hash cache; never re-bill an unchanged description.
- A failed batch must not discard successfully translated batches.
- Do not offer the action in a locale whose cards do not display the result.

## Boundaries

- Do not move, rewrite, enable or disable skill directories.
- The only writes are under `~/.dsh/skill-dashboard/` (override table, undo,
  translation cache, usage cache, skills snapshot).
- Tests must not call a real model; use a fake `llm.stream`.
- No telemetry. No network on page load.

## Issues and pull requests

- Triage labels: `needs-triage`, `needs-info`, `ready-for-agent`,
  `ready-for-human`, `wontfix`.
- A PR should state what changed, the evidence (tests or a screenshot), and
  whether it touches a boundary above.
- Include a before/after only when it makes the result easier to check; a
  passing `npm run check` is the minimum.
